# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Makeshift — "Scribblenauts meets Terraria." A 2D sandbox where players type descriptions to create game objects via LLM (Gemini), with sprites generated by Flux (fal.ai). A Python/FastAPI backend serves a Godot 4 client.

## Commands

```bash
make serve                     # run backend server
make test                      # run all tests
make check                     # lint + typecheck + test
make fix                       # autofix lint issues
make format                    # format code
make clear-sprites             # delete all cached sprites (backend/static/sprites/*.png)

# For more granular control:
uv run pytest backend/tests/test_tags.py  # single test file
uv run pytest -k "test_name"              # single test by name
```

## Architecture

**Backend** (`backend/app/`): FastAPI application with these key subsystems:

- **Object creation pipeline** (`creator/agent.py` → `routers/objects.py` → `images/pipeline.py` → `ws/handler.py`): Player text → PydanticAI agent (Gemini) → `CreatorOutput` (tags + behaviors) → placeholder PNG immediate response → background Flux sprite generation → WebSocket `sprite_ready` delivery. See [ARCHITECTURE.md](docs/ARCHITECTURE.md) for full 9-step flow.

- **Tag system** (`models/tags.py`): 30 `Tag` StrEnum values, 7 categories, power costs 1-5, budget of 10. 14 contradiction pairs enforced via `ModelRetry`. Tags define what objects *are* — physics, interactions, and durability. See [GAME_DESIGN.md](docs/GAME_DESIGN.md) for design rationale.

- **Behavior system** (`models/behaviors.py`, `models/blueprint.py`): 0-3 behaviors per object. Each behavior: trigger (10 types) + action (12 types) + target (5 types) + optional condition + categorical params (intensity, range, speed, interval). Budget of 6, separate from tag budget. See [ARCHITECTURE.md](docs/ARCHITECTURE.md) and [GAME_DESIGN.md](docs/GAME_DESIGN.md) for full detail.

- **Rule engine** (`engine/resolver.py`, `engine/rules_data.py`): `RuleResolver` — two-tier matching (O(1) pair index + O(n) wildcard scan). 43 rules. Mirrored client-side in Godot's `RuleEngine` autoload.

- **Image pipeline** (`images/pipeline.py`, `images/flux_client.py`): Cache-first. Flux Pro v1.1 (`fal-ai/flux-pro/v1.1`) → bg removal (local rembg or cloud birefnet) → resize by size_category → cache by SHA-256 hash of the Flux prompt.

- **Session persistence** (`sessions/manager.py`): aiosqlite, 2 tables (sessions, objects). Budget: $1.00 at $0.041/object.

- **WebSocket** (`ws/handler.py`): Per-session multi-client broadcast. Messages: sprite_ready, sprite_failed, error, ping/pong.

**Godot Client** (`godot/`): Godot 4.3, GDScript.

| Autoload | Purpose |
|----------|---------|
| `EventBus` | Central signal bus (10 signals: interaction_triggered, object_created, sprite_ready, sprite_failed, level_completed, creation_requested, creation_failed, placement_started, placement_ended, debug_toggled) |
| `Backend` | HTTP + WebSocket client, session persistence, sprite cache, 10s sync timer |
| `GameManager` | Game state (MENU/PLAYING/PAUSED), level management, scene transitions, `debug_mode` flag (toggled by `toggle_debug` input, emits `debug_toggled`) |
| `RuleEngine` | Client-side rule matching (mirrors backend resolver) |
| `CollisionResolver` | Per-frame collision resolution, cooldowns, cascade (depth 3, 96px radius) |
| `Logger` | Structured logging |

Key systems: `EffectExecutor` (12 effect types including DOT), `PhysicsApplicator` (tag-to-physics mapping), `BehaviorExecutor` (per-object autonomous behavior runtime, attached as child node when behaviors present), `BehaviorMaps` (categorical→numeric value mappings for behavior params), `DebugLabel` (floating per-object overlay showing name, durability, tags, and behaviors — visibility driven by `GameManager.debug_mode`). Player has two interaction modes: passive push (continuous impulse on slide collision, force 80) and kick (action input, 48px range, force 400, 0.5s cooldown).

## Data Model Flow

`CreatorOutput` (LLM output: tags + behaviors) → `GameObjectBlueprint` (adds id, computed `power_cost`/`behavior_cost`/`starting_durability`) → `WorldObject` (adds position, session context) → persisted as `objects` table row. Behaviors stored in existing `blueprint_json` column — no schema changes.

## Environment

Requires `.env` file (see `.env.example`):
- `GOOGLE_API_KEY` — Gemini LLM
- `FAL_KEY` — fal.ai Flux image generation
- `BG_REMOVAL_BACKEND` — `local` (rembg) or `cloud` (fal.ai birefnet). Default: local
- `SPRITE_CACHE_ENABLED` — toggles sprite cache read/write. Default: true
- Other settings have sensible defaults (budget $1.00, timeouts 15s/30s, max 3 concurrent images)

## Code Conventions

- Python 3.11+, type annotations throughout
- Ruff line-length: 100. Rule set: E, F, I, W, UP, B, SIM, RUF, PIE, C4, T20
- `creator/agent.py` is exempt from E501 (long system prompt)
- MyPy with Pydantic plugin; strict on untyped defs and implicit optionals
- Models use Pydantic v2 with `StrEnum` for enums
- Async everywhere in the backend (aiosqlite, httpx, FastAPI)

## Gotchas

- `pytest-asyncio` is configured with `asyncio_mode = "auto"` — `async def` tests run without extra markers
- Background `asyncio.Task`s must be held in a module-level `set` to prevent GC before completion (see `routers/objects.py`)
- Pydantic-AI validators raise `ModelRetry` (not `ValidationError`) to trigger agent retries with feedback
- `@computed_field` properties require `# type: ignore[prop-decorator]` — mypy still doesn't support decorators above `@property`
- WebSocket connection rejected with close code 4004 if session doesn't exist
- Sprite cache keyed by SHA-256 hash of the Flux prompt (first 16 hex chars), not object ID — identical prompts share sprites. Controlled by `SPRITE_CACHE_ENABLED` setting.
- `ON_TAG_ADDED` behavior trigger requires `trigger_tag` field; validated via `ModelRetry` in `Behavior.check_trigger_tag()`
- `CONTACT_BODY` behavior target is only valid with `ON_CONTACT`, `ON_DAMAGED`, or `ON_PROXIMITY` triggers — enforced by model validator
- `BehaviorExecutor` disables itself after 3 consecutive action errors to prevent runaway behavior on bad LLM output
- Behavior-added tags (via `ADD_TAGS` action) have a 10s duration; they auto-remove via decay timer in `GameObject.add_tag()`
- Movement conflicts resolved by fixed trigger priority: `ON_HEALTH_LOW` > `ON_TAG_ADDED` > `ON_DAMAGED` > `ON_CONTACT` > `ON_PROXIMITY` > `ON_TIMER` > `ALWAYS`
- `body_entered` collision handling is deferred via `call_deferred("_resolve_deferred", body)` — resolving collisions directly in the signal callback crashes Godot with "Can't change state while flushing queries" because resolution can chain into `add_tag` → `_reapply_physics` → new shapes
- Backend autoload uses `127.0.0.1` not `localhost` — avoids DNS resolution delays and IPv6 fallback issues on some systems
